## 3. 安全测试

- 超长字符串（每个字段的上限 + 1）；
- 非法 JSON、重复键、`NaN`/`Infinity`、深度嵌套；
- 超大消息（> 64 KiB）；
- 不支持的 `schema_version`；
- 无效签名 / 空签名 / 截断签名；
- 重放消息与重复 ID；
- 伪造 reviewer（非参与者）；
- 日志中不出现私钥（断言日志输出）；
- 精确坐标不进入广播摘要。

## 4. 人工验收（本地 UI 快速检查）

没有 Android 设备时可用 Chrome 预览：

```bash
flutter run -d chrome
```

1. 首页只有“发布需求 / 查看需求 / 本机身份 / 个人中心”，没有开发路线或功能清单长页；
2. 点“发布需求”，填写标题后提交，应回到列表并显示“签名已在本机验证”；
3. 列表应有 4 条带“示例”标记的需求，以及自己刚发布的需求；
4. 点右上角头像进入个人中心，修改昵称/头像并保存，首页问候语应更新；
5. 点“本机身份”，默认只显示身份状态；展开“开发者详情”（仅 debug 构建）后运行篡改测试，应显示“篡改后验签失败（符合预期）”。

> 开发用功能清单在 [`FEATURES.md`](FEATURES.md)，不在应用内展示。web 只用于本地预览；Android 真机与两台设备验收仍按下一节执行。

## 5. 人工验收（两台真机）

1. A 发布"从 X 到 Y"的出行需求；
2. B 提交响应；
3. A 选择 B，双方看到同一组条款；
4. 双方签署协议；
5. B 记录开始服务；
6. B 声明完成；
7. A 确认完成；
8. 双方各自评价对方；
9. 第三方设备能区分：协议事实 / 单方声明 / 评价；
10. 断开网络后，双方仍可查看本地记录。

## 6. 运行方式

工作区根目录：

```bash
dart pub get
dart test packages/osn_protocol
dart test packages/osn_identity
```

应用：

```bash
flutter analyze app/mobile
flutter test app/mobile
```

格式检查：

```bash
dart format --output=none --set-exit-if-changed app/mobile/lib app/mobile/test packages
```

> Windows 下若 `dart`/`flutter` 不在 PATH，用 `D:\Tools\flutter\bin\dart.bat` 与 `D:\Tools\flutter\bin\flutter.bat`。
