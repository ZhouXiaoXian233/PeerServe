# MVP 规格

## 1. MVP 必须实现

- [ ] 创建本地数字身份（密钥对）
- [ ] 显示并导出公钥身份标识、备份身份
- [ ] 创建需求公告（Request）
- [ ] 浏览已发现的公告
- [ ] 对公告发出服务响应（Offer）
- [ ] 发布者选择响应并建立协议（Agreement）
- [ ] 双方签署关键协议数据
- [ ] 追加交易事件：创建、响应、接受、开始、完成声明、双方确认、取消、争议
- [ ] 双方本地保存事件与对方签名
- [ ] 参与者针对已参与交易提交评价
- [ ] 评价必须引用有效协议，不能评价陌生人
- [ ] 通过 P2P 连接交换消息与事件
- [ ] 显示数据来源、签名验证结果、事实记录与评价的区别
- [ ] 导出/导入用户自己的数据
- [ ] 基本反垃圾：本地频率限制、大小限制、过期时间、屏蔽节点
- [ ] 自动化测试、协议文档、MIT 许可证与 GitHub README

## 2. MVP 暂不实现

- 真正的法币托管或退款
- 链上支付 / 区块链共识
- 统一全球信用分
- 自动仲裁、自动处罚、跨应用黑名单
- 完整商用安全保障、保险或法律合规体系
- 复杂地图路线规划
- 后台常驻、离线仍可被发现
- 面向生产环境的实名认证

## 3. 验收标准（两台设备）

1. 各自生成独立身份；
2. 通过可用的 P2P 连接建立联系，不经过项目方业务服务器；
3. A 发布任务，B 收到并显示；
4. B 提交 Offer，A 接受并生成 Agreement；
5. 双方对规范化协议内容签名并验证；
6. 双方追加完成相关事件，并明确区分"单方声明完成"与"双方确认完成"；
7. 参与者可提交评价，其他设备能验证评价签名及交易关联；
8. 修改签名后的内容会导致验签失败；
9. 关闭应用再打开，本地数据仍在；
10. 可导出并导入数据；
11. 没有任何中心 API 或中心数据库是上述流程的必需条件。
