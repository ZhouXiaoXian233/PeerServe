# 安全与隐私

> 状态：威胁模型与措施基线。当前代码尚未实现任何安全机制（Phase 0.1 只有 UI 外壳）。

## 1. 需要防护的风险

| 风险 | 场景 | MVP 措施 | 能否完全解决 |
| --- | --- | --- | --- |
| 伪造显示名 | 冒充他人昵称 | 身份标识由公钥派生，昵称仅作展示；UI 并列显示 ID 前缀 | 否（昵称本身无意义） |
| 篡改已签名数据 | 修改价格/时间后转发 | JCS + 域分离签名，逐字段验签 | 是（内容层面） |
| 重放旧消息 | 重发已失效 Offer | `nonce`、`expires_at`、`seen_messages` 去重 | 部分（离线节点仍可能收到旧消息） |
| 重复/洪泛 | 大量垃圾公告 | 速率限制、去重、TTL、大小上限 | 部分 |
| 畸形输入 | 超长字段、非法 JSON | 严格解析 + 长度/范围校验 + 64 KiB 上限 | 是 |
| 伪造评价 | 非参与者评价 | 校验 `reviewer_id` 属于该 Agreement | 是 |
| 私钥泄露 | 日志/备份/截图 | 私钥不进日志、不进仓库；备份加密 | 部分（设备被控无法防） |
| 设备丢失 | 手机被盗 | 系统锁 + 加密备份；MVP 不做远程擦除 | 否 |
| 位置隐私 | 精确定位被广播 | 默认只广播模糊区域；精确坐标按需交换 | 部分 |
| 女巫攻击 | 大量新身份刷评价 | 只展示"是否交易参与者 + 样本量"，不做全局分 | **否**（无中心即无法根治） |
| 网络分区 | 双方看到不同状态 | 冲突事件并存 + 明确标注 | 部分 |

## 2. 措施清单（按实现阶段）

**Phase 0.2（协议与身份）**
- 使用 `cryptography` 的 Ed25519，跑 RFC 8032 向量；
- JCS 规范化 + 域分离前缀；
- 所有 payload 禁浮点；
- 单元测试覆盖"逐字段篡改必失败"。

**Phase 0.3（存储）**
- 原始签名载荷入库，不只存渲染文本；
- 无效签名数据隔离，不进可信表；
- 数据库迁移事务化，迁移前自动备份。

**Phase 2（网络）**
- Noise/加密通道由传输层负责；
- 入站消息统一走校验流水线；
- 消息大小、速率、TTL、去重集合；
- 网络诊断页不泄露私钥与对方精确位置。

## 3. 明确无法解决的问题（必须写进 UI/README）

- 一个真实用户可以创建多个身份（Sybil）；
- 两个用户可以串通互刷好评；
- 签名不能证明现实陈述为真；
- GPS 可伪造、设备可被操控；
- 节点可离线或故意不转发；
- 已传播数据无法保证被所有节点删除；
- P2P 连接元数据可能暴露 IP；
- 无中心网络不保证全球搜索、持续在线、低延迟。

## 4. 隐私设计要点

- 默认最小披露：公告只公开"发现所需"的信息；精确地址、联系方式在建立联系后另行协商。
- 提供：任务过期、签名撤回、本地删除、本地屏蔽。
- 明确：远程节点可能保留副本，撤回不保证全网删除。
- 不把交易全文、位置轨迹、评价原文写入任何公共链（ADR-007）。
- 导出数据与身份备份都由用户自己保管，应用不代管。

## 5. 密钥处理

| 项 | 规则 |
| --- | --- |
| 生成 | 客户端本地生成 Ed25519 密钥对 |
| 存储 | 系统安全存储（Keystore 包裹）或 AES-GCM 加密文件；数据库中不存明文 |
| 使用 | 签名在软件层完成；不依赖 Keystore 对 Ed25519 的原生支持（各厂商不一致） |
| 备份 | 口令经 Argon2id 派生 → AES-GCM 加密文件；口令不写日志 |
| 日志 | 任何级别日志都不得包含私钥、助记词、备份口令 |
| 丢失 | 无法恢复原身份；必须在 UI 明确告知 |
